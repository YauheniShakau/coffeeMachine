# Repository instructions

## README changes

- Lead with the project's purpose and a reproducible example. Link the main files and guides. Give the prerequisites, commands, and expected result. Keep deployment, recovery, and change history in dedicated documents.
- If a pull request changes behavior, commands, paths, or a screen shown in the README, update the affected guide and demo in the same pull request. Verify claims against the source or a recorded observation. Give each fact one primary home and link to it elsewhere.
- Keep screenshots and slide decks in `docs/readme/`. Label captures as a live site, local test, sample interface, or source excerpt. Use public or synthetic data, add descriptive alt text, and give the units, source, and conditions for any measured number.
- Before merging, preview the Markdown on GitHub and verify relative links, diagrams, images, PDFs, and commands. Record what ran and what remains unverified in the pull request.
